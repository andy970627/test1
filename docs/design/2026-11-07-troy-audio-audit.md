# 《木馬之夜》Risset 節奏層稽核

日期：2026-11-07　範圍：`prototypes/troy-prologue/risset.js`、`audio.js`、`index.html`、`tools/playtest-recorder/`、設計文件第 7、8 節（提交 8bbe52b）
由稽核代理只讀、只算、只錄，不改檔。計算腳本與錄音輸出在雲端暫存，不入庫。

## 1. 結論

- **層數**：4 層打擊（低鼓、框鼓、手拍、金屬）＋追殺時第 5 層。核心公式和 Risset 原理一致：拍點 2:1 對齊、交接連續、四層音量和恆定（起伏 0.2%），**沒有算錯**。
- **錯誤**：共 15 個，會讓玩家聽出來的 2 個（追殺層不照鐘形曲線、假驟降交接有 3 dB 落差），其餘是數字邊界或文件不一致。
- **錄音分析**：5 項全過（這次沒走到第 3 區，假驟降與追殺沒錄到）。

## 2. 層數摘要

常數：`RISSET_LAYERS` 4、`RISSET_M` 7、`BELL_SIGMA` 0.22、`BEAT_MIN_GAIN` 0.02、`HUNT_FLOOR` 0.55、`HUNT_LAYER_GAIN` 0.4。第 k 層第 n 拍相位 p = log2(1 + n ÷ (7·2^k))，音量 bell((k+p)/4)。

| 層 k | 每循環拍數 | 速率（拍/秒，T=12／6／4） | 音量 p=0 → p=1 | 音量 ≥0.02 的拍 |
|---|---|---|---|---|
| 0 低鼓 | 7 | 0.4→0.8／0.8→1.6／1.2→2.4 | 0.006 → 0.275（淡入） | 5/7 |
| 1 框鼓 | 14 | 0.8→1.6／1.6→3.2／2.4→4.9 | 0.275 → 1.000 | 14/14 |
| 2 手拍 | 28 | 1.6→3.2／3.2→6.5／4.9→9.7 | 1.000 → 0.275 | 28/28 |
| 3 金屬 | 56 | 3.2→6.5／6.5→12.9／9.7→19.4 | 0.275 → 0.006（淡出） | 38/56 |
| 4 追殺額外層 | 112 | T=3：25.9→51.8 | 固定 0.4，不淡入淡出 | 全部 |

- **2:1 對齊**：第 k 層第 n 拍 ＝ 第 k+1 層第 2n 拍，相位差 0。
- **交接連續**：p→1 時第 k 層音量 ＝ p→0 時第 k+1 層音量（0.275、1.000、0.275）；速率也接上。T=6 時跨循環的拍距 0.693 → 0.641 → 0.597 秒單調縮短，沒有接縫。
- **沒有谷**：四層音量和 1.556～1.558；任一時刻最響層最低 0.724。
- **盲區 0.6 秒內略過的拍**：T=12 略過 4、T=6 略過 10、T=4 略過 13、T=3 略過 17（每循環 105 拍、可聽 85）。假驟降時照響，第一拍是最響的 k2 n0（音量 1.0）。

## 3. 錯誤清單（15）

嚴重度：【聽得出】／【數字】只影響邊界或邏輯／【文件】只是文字。

### 規則層 `risset.js`（3）
- **R1**【聽得出，可能是刻意】`layerGain` 第 211–217 行：追殺時 `HUNT_FLOOR` 0.55 讓第 3 層在 p→1 仍以 0.55 響著被截掉；第 5 層固定 0.4 不淡入淡出。T=3 時第 5 層 25.9→51.8 拍/秒已超過人耳分辨節拍的上限，聽到的是嗡聲，每次交接都有接縫。若「追殺＝失控」是刻意，文件要寫明。
- **R2**【數字】`beatsBetween` 第 264 行用 `ph × an.T < BL` 判盲區，`updateClock` 第 761 行用 `t − c.start < BL`。T 在循環內變化時兩者可差到 0.3 秒，邊界拍兩邊判定不同；anchor 已帶 `start` 卻沒用。
- **R3**【文件】第 122 行 `ESCAPE_STILL: 10 // = 一整個循環`、第 314 行提示「撐過一整個循環（約 10 秒）」：追殺循環是 3 秒，說法已不成立。

### 聲音層 `audio.js`（4）
- **A1**【聽得出】第 1049 行 `tension.gain = 0.7 + 0.3·frac(p)`：節奏匯流排隨 p 從 0.7 漲到 1.0，交接瞬間掉回 0.7（−3.1 dB）。真盲區有靜音蓋住沒差，但**假驟降**要求無縫，這 3 dB 就是可聽的接縫。
- **A2**【數字】第 987、992 行追殺層音量寫死 0.4、`bell` 用本檔複本的 σ、層數、M；`update(state)` 只從規則讀 `BLIND_LEN`。規則一改常數，拍點會跟、音量與音色位置不跟。
- **A3**【數字】第 997 行音量抖動 ×(0.95～1.05) 加 A1 的 tension，使實際響度 ≠ 規則 gain；`stepMasked` 只看規則 gain ≥ 0.3，邊界拍會誤判「蓋得住腳步」。
- **A4**【數字】假驟降的金屬尾音（`FAKE_TAIL_GAIN` 0.035）只在聲音層，規則與畫面都沒有；是「規則是唯一來源」的例外，但不影響判定。

### 畫面層 `index.html`（2）
- **V1**【數字】第 1136、1172–1182、1255 行把 M=7、4 層、σ 0.22 寫死，音量備援門檻 0.05 和規則的 0.02 不一致。主要路徑用 `Rules.beatsBetween`，拍點本身正確。
- **V2**【數字】第 1159 行 `collectBeats` 在 `visBlind()` 為真時整幀回空，盲區結束那一幀內已響的拍不會跳動，盲區後第一拍（最響的那拍）常被吃掉。

### 錄音分析層 `tools/playtest-recorder/`（2）
- **P1**【數字】`profiles/troy-prologue.mjs` 第 203–235 行 `expectedBeats` 自己抄一份拍點公式，常數來自聲音層；規則與聲音分歧時分析會站在聲音那邊。
- **P2**【數字】同函式只算 4 層，追殺第 5 層與假驟降尾音不在期望拍裡，追殺區段的丟拍統計會失真。

### 設計文件 `2026-11-06-risset-troy-prologue.md`（4）
- **D1** 第 20、22、82、84 行仍寫「T＝10 秒」「盲區 0.5 秒」，程式與 8.1 節是動態 T 與 0.6 秒；6.2 節沒標「已被 8.1 取代」。
- **D2** 全文沒寫 Risset 層的實際參數（4 層、7·2^k 拍、σ 0.22、0.02、追殺層 0.4 與底限 0.55）；R1 的設計意圖找不到依據。
- **D3** 第 128–129 行「盲區時所有聲音都休止」，實作是分層壓低：節奏 −30 dB、音樂 −40 dB、衛兵 −22 dB、暗示 −46 dB，低音與玩家自己的音效不經 gate。
- **D4** 8.4 節 `anchor:{t, p, T}`，程式是 `{t, p, T, index, start}`，且聲音層用相鄰兩次 anchor 估 T 的斜率外推，不是純線性。另 6.2 節「8 秒內沒完成安撫」vs `CALM_TIMEOUT` 12。

## 4. 錄音分析（90 秒，第 1～2 區）

5 項全過：盲區比前後低中位 36.5 dB（14 次）；Risset 起音誤差中位 2.3 ms、±30 ms 命中 96%（386 拍），低音中位 3.5 ms、命中 85%；警戒低頻 −25.1 dB > 中頻 −28.1 > 高頻 −35.1；削峰 0、峰值 −0.9 dBFS；無聲段 0、丟拍 2.7%。16 次盲區都是 0.6 秒；13/13 次一般盲區前有預告音。實際 T：巡邏 5.4～9.2 秒、警戒 4～6 秒。
頻譜圖：每個盲區是乾淨的垂直空白，兩側沒有拖尾；打擊條紋往右越來越密；包絡在盲區壓到約 −65 dBFS，結束後 0.25 秒內回到 −20 dB，交接處沒有台階或爆音。
