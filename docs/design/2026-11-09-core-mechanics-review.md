怎麼來的：使用者 11/09 第二輪真耳朵試玩（喇叭）後決定「先重審核心、文件先行」。初稿由兩個外部模型各寫一份（agy：Claude Opus 4.6、Gemini 3.8 Flash，不吃 Claude Code 額度），主對話逐項對照 `risset.js` 常數表核對後合併重寫。來源標記：【甲】Opus 4.6 初稿、【乙】Gemini 初稿、【主】主對話。被剔除的：乙稿「N1 現行實測約 9%」（沒有量過）、乙稿把「求婚者逼近」放進比箭原型（兩個原型搞混）、乙稿 M10 投擲陶片（它自己也說偏離音樂主軸）。

## 4. 三套組合方案

前提【主】：Claude 週用量 11/09 晚已 80%，**11/10 22:00（台北）才重置**；四個角色工作階段實作大約各一輪 20～30 萬 token。所以 11/10 白天只能做規則層的小改與測試，大部分實作落在 11/10 晚到 11/11；11/11 晚試玩。兩份初稿估的「11/10 傍晚完成」在這個限制下不成立。

### 4A　保守（11/11 試玩目標；建議的最小集合）
- 採用：**M2 追殺生路、M3 行動回饋、M4 火光綁速度、M7 感知放遠（只改常數，不做分級）、M8 漸進後果**。
- 規則：新常數 `DASH_HUNT`、`HUNT_STEP_ESCAPE`、`FAKE_SUSP_JUMP`、`ALERTED_DURATION`、`FIRE_BASE`／`FIRE_P_GAIN`／`FIRE_BLIND`；改 `ESCAPE_STILL`、`R_BASE`、`R_GAIN`；衛兵新狀態 `alerted`；`move_high` 改進高度警覺；匯出 `fireBrightness(p)`；順手補匯出 `blindWindows`（聲音層已在等）。測試補新狀態與 G4、G5 程式玩家。約 3～4 小時【甲】。
- 聲音：`dash` 風聲、`takedown` 低咚、`alerted` 嗡鳴、追殺合拍確認音；大廳復仇不動。約 2～3 小時。
- 畫面：速度線、白閃、火光亮度讀規則、衛兵火把顏色、追殺殘影。約 2～3 小時。
- 對報告：可講「追殺有解、犯錯不即死、每個動作有回饋、看火光就知道多危險」。等待問題只緩解。
- 風險：N1 仍可能 ≤ 30%（假設，待量）；若使用者 11/11 仍覺得「都在等」，要追加 M1。

### 4B　中（11/11 試玩很緊，可能落到 11/11 晚）
- 採用：4A 全部＋**M1 多強度時機（弱拍走）、M9 教學重排、M11 屏息心跳**。
- 額外規則：弱拍窗判定 `step_weak`（p ≤ `WEAK_P_MAX` 且拍音量 ≥ `MASK_GAIN`）、p 0.4～0.6 的 `SUSP_MOVE_MID` 1.8、區域重排（`FAKE_FROM_ZONE` 4）。約再 3～4 小時。聲音再 1～2、畫面再 2～3、測試再 2。
- 對報告：可講「多時機＋火光＋教學順序」，N1 估 45～55%（假設，待量）。
- 風險：弱拍判定的邊界條件（拍音量 ≥ 0.3 的拍在 p 0.3～0.4 很密）可能卡；11/11 做不完就只能拿 4A 的版本試玩。

- 採用：全部 M1～M13，含 M5（大廳復仇踩拍箭綁逼近）、M6（比箭距離）、M10（木馬腹中練習）、M12（假減速）、M13（門閂對拍）。

## 5. 建議與抉擇順序【主】

**建議：4A 當 11/11 的試玩目標，M1（弱拍走）當 4A 做完後的第一個追加項，不要一開始就排進去。** 理由：
1. 用量限制讓 11/10 幾乎沒有可用的實作時間；4A 五件都是「改常數、加狀態、加回饋」，彼此獨立、三層可平行，是兩天內最可能做完又真的改變手感的集合。
2. 使用者這輪最強的兩句是「紅色階段逃不掉」和「不知道做對了沒」，4A 的 M2、M3、M8 直接對這兩句；M4 是三個常數加一個公式，換來「看一眼就知道多危險」。
3. M1 才是對「大部分時間在等」的正解，但它改的是判定核心，邊界條件多；放到 4A 之後做，11/11 試玩若來不及也不會拖垮整批。
4. 和大廳復仇 v2 的方向一致（v2 的揮砍拍就是「多個可踩的時機」），兩邊不會各走各的。

**給使用者的選擇題**（主對話用 AskUserQuestion 問；每題第一個是建議）
1. 方案：4A（建議）／4B／4C。
2. 追殺合拍脫離要幾步 `HUNT_STEP_ESCAPE`：3 步約 1.35 秒（建議）／2 步／4 步（超過 1.8 秒會變成估時間，規則 5）。
3. 高度警覺持續 `ALERTED_DURATION`：10 秒（建議，約 1～3 個循環）／6 秒／到循環結束。
4. 教學：M9 重排區域（建議，只改常數）／M10 木馬腹中練習（要做新小場景）／兩個都要（報告後）。
5. 若選 4B：弱拍安全上限 `WEAK_P_MAX` 0.4（建議，和 `HIGH_P` 0.6 之間留 0.2 的中段危險區）／0.3／0.5（和 `GATE_LOW_P` 對齊）。

實作分工（照角色檔案切，主對話整合）：規則角色先做 4A 的規則與測試（其他兩層依賴它的新事件名與 `fireBrightness`），聲音與畫面角色等規則回「事件名定了」再接；錄音與工具角色加 `fireSync`、`heartbeatSync`（若選 4B）兩項檢查並修本機 playwright 與 `NODE_PATH`。

## 6. 和 13 條搭配規則的對照

| 規則 | 相關提案 | 處理 |
|---|---|---|
| 1 有呈現才判定 | M3、M4、M1 | 遵守，M3 就是在補這條 |
| 2 判定窗以秒計 | M1 弱拍窗由 `STEP_WIN` ±0.08 秒決定 | 遵守 |
| 3 一區只教一件事 | M9／M10 | 遵守（G6） |

| 7 規則是唯一來源 | M4 由規則匯出 `fireBrightness(p)`；順手匯出 `blindWindows` | 遵守 |
| 8 選擇多於反應 | M1、M2 | 4A 只部分滿足；4B 才達 G2 |

| 10 壓力頂端放威脅不放精準輸入 | M1 安全走在 p ≤ 0.4（低壓）；M8 高速移動的後果是疑心而非精準要求 | 遵守 |

| 12 數字只有一份 | 新常數進 `T`、提示由 `hintsFor` 生成；`ESCAPE_STILL` 的提示文字已由常數生成 | 遵守 |
| 13 音樂層避開功能層頻段 | M11 心跳 400～800 Hz 與框鼓中頻重疊 | **碰到**：心跳只在屏息中播、音量低於鼓 6 dB（假設）；真耳朵不行就改 M3 的脈動只用畫面 |
