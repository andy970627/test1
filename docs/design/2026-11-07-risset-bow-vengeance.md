# 比箭與大廳復仇：套用 Risset 音樂原理（原型比較）

日期：2026-11-07　狀態：使用者決定現在派代理做原型，和現有比箭、木馬之夜比較
出處規則：大眾熟知的經典段落為主（`CLAUDE.md`）。比箭、殺求婚者【經典】；配樂曲名〈The Trial of the Bow〉〈Vengeance〉【電影】只參考氛圍，不使用。

## 1. 原理回顧

Risset 節奏是幾層速度相差一倍的節拍同時加速，最快的一層淡出、最慢的一層淡入，聽起來永遠在加速。謝帕德音階是它的音高版本，聽起來永遠在上升。木馬之夜把「交接那一刻」做成 0.6 秒的空檔（盲區），當作行動時機。

## 2. 比箭 Risset 版（`prototypes/bow-risset/`）【改編】

和現有比箭（`prototypes/bow-contest/`）放在一起比較，核心目標一樣：一箭穿過 12 個斧孔。

| 階段 | Risset 版的做法 |
|---|---|
| 上弦 | 拉弦時謝帕德音階一路上爬，像弦越繃越緊、永遠到不了頂；指針平衡玩法照舊 |
| 拉弓瞄準 | 心跳是 Risset 節奏，越來越快，準心跟著心跳晃動，而且越晃越大 |
| 放箭時機 | 驟降那一瞬間（約 0.5 秒）心跳斷掉、全場靜止、準心最穩，取代原本的呼吸判定；在最高速時放箭最不穩 |
| 箭飛行 | 慢動作，每穿過一個孔，奏出主題動機的下一個音（主題沿用木馬之夜的，當作閃回），12 孔奏完 |
| 求婚者起鬨 | 在節奏最快時起鬨，干擾最大；驟降時一起噤聲 |

比較重點：「抓驟降放箭」和原本的「抓呼吸吐氣到底放箭」，哪個比較直覺、好玩、有張力。

## 3. 大廳復仇（`prototypes/vengeance/`）【經典＋改編】

核心玩法（使用者選定）：**節奏動作戰鬥**。求婚者在節奏最高速時出手，驟降的空檔是你反擊的時機。

- 第一人稱，站在大廳門檻上，手持剛穿過斧孔的弓（接續比箭）。
- 求婚者分散在大廳，依 Risset 節奏一波一波逼近：節奏越快，他們越靠近、越兇；最高速時有人出手（擲矛、撲上來），要用閃避或屏息躲開。
- **驟降空檔**：可以射箭（瞄準一名求婚者），一次空檔射一箭；在空檔外放箭會失準、暴露位置。
- **忒勒馬科斯**跟著慢低音配合你：在低音拍上按鍵，他會舉盾擋下一次攻擊（借用木馬之夜的安撫節奏）。
- **箭數有限**（例如 12 支，呼應 12 把斧頭），射完要撿。
- 勝利：最強的幾名求婚者倒下、其餘投降【電影】。不寫血腥細節。
- 規則和畫面分開（`vengeance.js` 純邏輯＋測試，`index.html` 畫面），聲音沿用木馬之夜的 Risset 做法（複製必要函式，註明來源）。

### 3.0 按鍵配置（11/08）【改編】
左手 WASD 走位、Shift 閃避、空白鍵屏息；右手滑鼠：左鍵放箭、**右鍵舉盾（和 Q 同效）**。節奏鍵放右手，邊走位邊跟低音按才不會和 WASD、Shift 打架。

### 3.1 難度預設【改編】（11/07）

開場字卡選一段，三顆按鈕；HUD 左上角標出目前難度與這一輪的拍數。規則層 `createGame({difficulty})` 用預設覆寫常數表 `T`，產生這一局的 `game.T`；畫面與聲音都讀 `game.T`。數字和 `vengeance.js` 的 `DIFFICULTY` 一致，測試有覆蓋。

| | 輕鬆 | 標準 | 殘酷 |
|---|---|---|---|
| 一輪的長度 | 4 拍 **9.6 秒** | 3 拍 7.2 秒 | 2 拍 **4.8 秒** |
| 空檔（驟降） | 0.6 秒 | 0.6 秒 | 0.6 秒 |
| 閃避窗口（命中前） | 0.5 秒 | 0.35 秒 | 0.25 秒（冷卻 0.4 秒） |
| 每輪出手兩次 | 永遠不會 | 倒下 2 名頭目後 | 倒下 1 名頭目後 |
| 預備提早 | 0.9 秒 | 0.9 秒 | 0.7 秒 |
| 空檔外放箭偏差 | ±0.2 弧度 | ±0.2 弧度 | ±0.3 弧度（俯仰 ±0.15） |
| 箭 | 14 | 12 | 10 |
| 生命 | 4 | 3 | 2 |

- **輕鬆為什麼是 4 拍 9.6 秒，不是 8.4 秒**：循環必須是整數個低音拍，驟降才會永遠落在低音網格的同一個位置（兩拍正中間），忒勒馬科斯的拍子才不會被打斷；3.5 拍做不到。另一個做法是維持 3 拍、放寬空檔，但空檔長度三段都要一樣（和木馬之夜一致：速度只改驟降出現的頻率，不改窗口），所以選 4 拍。
- **殘酷的兩次出手**：p = 0.88、0.97 在 4.8 秒裡只差 0.43 秒，比標準的閃避冷卻 0.6 秒短，所以殘酷的冷卻縮到 0.4 秒，兩下都抓準才躲得掉；預備提早 0.7 秒是為了讓預備仍落在最高速（p ≥ 0.73）。
- **程式玩家勝率**（`vengeance.test.js` 最後一項，每段 50 局、幀率 8～15 fps）：完美玩家三段都 50/50（平均通關 58／46／32 秒）；模擬一般玩家（熟練度 0.6：每個低音拍 40% 忘了按 Q、每次攻擊 40% 反應慢 0.3 秒）：輕鬆 **50/50**、標準 **45/50**、殘酷 **21/50**，平均受傷 0.44／1.38／1.42 次。

### 3.2 越危險越快【改編】（11/07）

開場字卡的開關，`createGame({dynamic: true})`。做法和木馬之夜 8.1 節不同：那邊依距離平滑變速，這邊**只在循環交接時換長度**，而且一律整數拍。

| 還站著的頭目 | 一輪的拍數 |
|---|---|
| 4 名 | 該難度的基準（輕鬆 4、標準 3、殘酷 2） |
| 每倒 1 名 | 少 1 拍 |
| 下限 | 2 拍（4.8 秒） |

- 輕鬆：4 → 3 → 2 → 2；標準：3 → 2 → 2 → 2；殘酷本來就是 2 拍，開了也不會更快（開場字卡會註明）。
- **交接時才決定**：這一輪中途放倒頭目，這一輪不變，下一輪開始的那一刻（規則 `commitCycles`）才依當時的頭目數定長度，發 `cycle` 事件；之後 `cycleOf(game, t)` 查任何時間的循環，還沒交接的未來循環先用目前的目標長度估。
- **驟降永遠落在低音網格上**：每輪都是整數拍，所以每次驟降都在兩個低音拍正中間（離最近的拍 1.2 秒），低音網格 `t0 + 1.2 + k·2.4` 從頭到尾不中斷、不重排，忒勒馬科斯的拍子照常。空檔仍 0.6 秒。
- **聲音層讀規則**：`audio.js` 不再自己用 `t0 + c·CYCLE` 算拍點，改由畫面層傳 `cycleAt(t) = VengeanceRules.cycleOf(game, t)`，逐輪照規則的起點與長度排 Risset 拍。空檔 0.6 秒比預排前視 0.5 秒長，所以下一輪的拍一定在交接之後才排，長度定案前不會排錯；依長度的自動化（張力、低吼）也等交接後才排，只有不依長度的驟降 gate 提早 0.08 秒排。
- 畫面：交接時節奏條的低音記號與右下角的低音圓點改成這一輪的拍數，HUD 難度標籤顯示「標準・越危險越快・2 拍」，縮短時提示一行「鼓聲更急了：一輪只剩 2 拍」。
- 程式玩家開了開關通關更快（標準 46 → 36 秒），勝率不變。

## 4. 比較方式

用專案的錄音工具（`tools/playtest-recorder/`）各錄一輪，比較：
- 聲音檢查：驟降空檔是否夠安靜、拍點準確度。
- 程式玩家的勝率與通關時間。
- 主觀試玩：由使用者判斷。
