# 雙盲洞穴網頁版：和主線設計的綜合分析

日期：2026-11-22　狀態：**分析與建議，等使用者選方向**；本文件不改玩法。
依據：`blind-cave` 分支規格 `docs/superpowers/specs/2026-10-10-blind-cave-design.md`、`2026-10-10-blind-cave-v2-design.md`（第 19、30、31、33 節）、`Assets/Odyssey/Core/`；網頁原型 `prototypes/blind-cave-web/`。

## 1. 結論

現在的網頁房間只驗證「聽得出方向」，還不是《雙盲洞穴》。主線的核心是**你發出的聲音同時是你的眼睛和巨人的耳朵**（規格第 4 節：「你看得多遠，他就聽得多遠」），網頁房間裡玩家完全不必出聲，所以少了這個取捨。

建議做**「一夜縮小版」**：保留網頁房間新做出來的耳機定位和觀眾地圖，從主線移植聲音法則、會追聲的巨人、引開再推巨石這個循環，其餘系統都不搬。

## 2. 網頁房間和主線的對照

| 項目 | 主線 | 網頁房間 | 判斷 |
|---|---|---|---|
| 配音 | 沒有配音，也沒有音檔；引導是吟遊詩人文字詩句（第 31 節 D） | 原本用系統合成語音，**11/22 已拿掉，只留字幕** | 已一致 |
| 海風指路 | 全洞聽得到，靠近縫更明顯（第 19 節 C） | 海風浪聲是出口方向 | 一致，HRTF 更清楚 |
| 滴水 | 只有聲音，巨人不理（第 33 節 A） | 固定地標，不影響勝負 | 一致 |
| 巨人前提 | **已被刺瞎**，醒著在洞裡聽聲 | 睡著打鼾，失敗句是「睜開那隻獨眼」 | **衝突**，要改 |
| 玩家的聲音 | 腳步、拍手、石子都有聲量，巨人聽得到 | 沒有 | **缺核心** |
| 看見東西 | 主動出聲才有回聲照亮 | 全黑，只有聽 | 缺，可做成簡單聲波 |
| 巨人行為 | 聆聽、追聲、摸索、守石 | 固定不動，靠近就失敗 | **缺核心** |
| 出口 | 巨石封住，推滿 8 格才鑽得出去 | 開著的洞口，走到就贏 | 缺目標壓力 |
| 失敗 | 被摸到（2 m）或撞到（1 m） | 進入 2.2 m 圈 | 改用主線規則 |
| 觀眾地圖 | 只有開發用 F1 面板 | `?spectator=1` | **網頁版新增的賣點** |
| 耳機定位 | Unity 3D 音效 | HRTF（模擬耳朵濾波的立體定位）＋前後音色 | **網頁版新增的賣點** |

## 3. 建議的綜合設計：一夜縮小版

**一句話**：黑暗裡，奧德修斯聽著海風找到被巨石封住的洞口；每個聲音都能幫他看見，也會把瞎眼的巨人引過來。

### 從主線搬過來

| 內容 | 做法 | 出處標記 |
|---|---|---|
| 聲音法則 | 半徑＝聲量 × 20 m。蹲走 0.15（3 m）、跑 0.4（8 m）、拍手 0.5（10 m）、石子 0.6（12 m）、推巨石 1.0（20 m） | 【改編】 |
| 主動照亮 | 拍手、石子落地、推巨石才有一圈回聲，走路不亮 | 【改編】 |
| 巨人 | 只搬聆聽、追聲、摸索三態；走速 3.5 m/s，摸索 2 m，碰撞 1 m | 【經典】瞎眼巨人＋【改編】 |
| 引開再推 | 丟石子把巨人引走，趁機推巨石；格數從 8 降到約 3 | 【經典】巨石封洞＋【改編】 |
| 文字引導 | 吟遊詩人式第三人稱字幕，加一行按鍵提示，不配音 | 【改編】 |

### 明確不搬

同伴、木樁、楔子、巨石物理、弓、彈弓、宙斯法則、雅典娜、羊群、多夜循環、禱告。它們依賴主線的 3D 場景或長流程，單人在 12/24 前做不完，也不是回答核心問題所需。

### 班展呈現

玩家看不見、巨人看不見，**只有觀眾看得見**。觀眾地圖同時畫出玩家、巨人和每個聲音擴散的半徑，觀眾會看到玩家一拍手巨人就轉頭。「雙盲」在現場第一次變成看得到的東西，這是 Unity 版沒有的部分。

## 4. 三條路比較

| | A. 一夜縮小版（建議） | B. 直接打包 Unity 成網頁 | C. 維持聽聲找路小品 |
|---|---|---|---|
| 做法 | 把聲音規則和三態巨人移植到 `cave.js`，房間沿用 | 走主線既有 WebGL 流程，加觀眾視圖 | 只修文字和調手感 |
| 好處 | 有主線核心、載入快、能自動測試、觀眾地圖已通 | 內容最完整 | 最省工 |
| 代價 | 約移植 `SoundRules`（91 行）和 `CyclopsBrain`（497 行）的一部分；兩邊規則會分家 | 從未真正建置過網頁版，要 Unity 授權；HRTF 和跨視窗同步都要重做 | 玩法單薄，撐不起期末 |
| 改回難度 | 低，房間和聲音層都能留用 | 高，綁定 Unity 建置 | 低 |

## 5. 風險與待驗證

1. **聽不聽得出方向還沒有真人驗證。** 這是整個方向的前提。動工做 A 之前，最好先請 2～3 人戴耳機試現有房間。
2. **房間可能太小。** 20×14 公尺裡，石子 12 m、拍手 10 m 幾乎蓋住半間以上，主線數值可能讓巨人什麼都聽得到，要用程式玩家量過再調。
3. **和上次報告重複。** 主線洞穴已經報告過，期末要講清楚新東西是網頁耳機定位和觀眾視角；是否算新作品，要看老師標準。
4. **只有字幕時，全黑畫面要讀字。** 字幕只放開場和結局，遊戲中盡量靠聲音，避免玩家一直盯著字。
