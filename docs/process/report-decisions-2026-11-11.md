# 11/12 報告定案（2026-11-11 深夜，設計席記錄使用者的決定）

給報告角色一次改稿用。稿子本身改 `report-outline.md` 與簡報；`report-structure-draft.md` 有使用者自己未提交的修改，不要動。
先記事項的來源：`docs/design/2026-11-11-illusion-not-heard.md` 第 6.2、8 節（共 13 項）。

## 1. 使用者定的事

| 題 | 決定 |
|---|---|
| 主軸 | **錯覺是主題，進度照實講** |
| 影片 | 原話：「報告用影片呈現遊戲最新進展即可，所以不用盡善盡美」。用錄影當下最新的版本，錄到哪算哪。不訂凍結點、不為報告重跑整套數字 |
| 開頭 | 用聲音試聽頁的版本對照來講音樂原理。用哪幾段沒有偏好，先用「現行 → U1 → U4」；第三輪試聽若選出更好的一版就換 |
| 新鼓聲什麼時候進遊戲 | **等第三輪試聽選出最好的再套**。所以錄影時遊戲裡的鼓可能還是舊的四層，也可能已經換了，看進度 |

## 2. 一句話主軸

我們想做的是電影《奧德賽》配樂裡那種「一直在加速」的節奏錯覺，並把它變成潛行的規則。現在做到的是：鼓聲不中斷，最響的那一擊成了玩家聽得出來的時機。「一直在加速」的感覺，第一次真耳朵試玩沒有成立；我們用幾輪試聽找到了原因，還在調。

## 3. 各段要改的重點（時間分配沿用 `report-outline.md`）

- **音樂原理**：改用我們自己的試聽頁放三段，各約 12 秒。「我們的改法」那一句整段換掉：舊稿寫「故意留 0.6 秒空白」，那是 11/10 以前的做法；現在是鼓聲不中斷，在節奏裡放一個最響的一擊，那一擊和它的迴盪蓋得住玩家的聲音。出處標【電影】，並註明參考的那支影片是作者的重現，不是原曲分析。
- **試玩影片**：最新版，有什麼錄什麼。能錄到的優先順序：踩著鼓點走 → 趁最響的一擊跑或暗殺 → 被追殺時躲進影子、屏息、聽腳步 → 城門。大廳復仇那 15 秒還是舊的「留空檔」做法，和主軸不一致，建議拿掉。
- **製作過程**：時間軸補到 11/11。轉折講這一個：程式玩家說時機認得出來、能通關，真人戴上耳機卻說聽不出在加速；兩種測試量的是不同的事。
- **說明與下次改進**：第 4 節那幾件。

## 4. 要照實講的（不要潤掉）

1. 錯覺在遊戲裡還沒成立。真耳朵原話：「聲音不夠快到發揮錯覺設計……其實是不同層疊加蓋過效果」。
2. 找到的原因：層太少、快的那條鼓沒淡完就被切掉；修好之後（U1）使用者說「最有營造出錯覺」；剩下的是最響的一擊每圈固定在同一個位置，標出了循環，下一步是讓它的間隔不固定。
3. 開頭試聽到的新鼓聲如果錄影時還沒進遊戲，要說一句，免得觀眾以為遊戲裡就是那個聲音。
4. 提到通關率、時間時都帶「程式玩家」，並說是哪一版。數字不用多，挑兩三個；舊版改版前後的對照（同一把尺 77% → 96%、完美的程式玩家 87 秒 → 44 秒）可以用，標明是 11/10 那次改版。
5. 關卡的問題：完美踩拍的程式玩家 46.7 秒通關、0 次警戒，其他機制用不到。下一步是重排關卡。
6. 今天新加的（跑、蹲、屏息時聽腳步、追殺重做、拿掉安撫改成衛兵過來查看）哪些做完、哪些還沒，照錄影當下的狀況說；真人只試過一部分。
7. 真耳朵確認過的好消息也要講：最響的一擊在耳機上各版都好認；衝刺的速度感足夠。
8. 引用研究裡的數字之前對原文確認一次；沒確認就只寫結論、不寫數字。
