## 各階段

### 1. 盤點發想（11/01）
- **需求**：「找出主線遊戲之外的其他發想概念，抓出適合做成網頁遊戲的」。
- **做法**：讀遍 `main` 和遠端各分支的規格、計畫、提交紀錄。發現最大的一份《奧吉吉亞：第七年》總綱只在 `blind-cave` 分支。
- **結果**：11 個概念依「一輪夠短、操作簡單、能單獨成立」評分，建議先做伊薩卡比箭。→ `docs/design/2026-11-01-web-game-candidates.md`

### 2. 新概念：門檻上的乞丐（11/01）
- **需求**：裝成乞丐的潛行，不能被發現、不能被羞辱到死、要能潛入主廳，要有創新機制。
- **結果**：核心反轉「一定會被看見，只是不能被看穿」；疑心／怒火／身體三方拉扯；視線高度＝潛行等級、乞討當通行證、笨拙地閃、剛好贏的拳鬥、羞辱存成復仇。→ `docs/design/2026-11-01-beggar-stealth-concept.md`

### 3. 路線分析（11/02）
- **問題**：先做網頁，之後換平台、架構或引擎會不會浪費 token。
- **結論**：只換平台幾乎不浪費；換引擎才貴，貴在畫面、操作和手感。真正浪費的是「動工前沒定視角」和「規則與畫面混寫」。這個結論後來直接決定了第二版的架構（第 6 段）。

### 4. 整理成總覽（11/03）
- 使用者要求「不確定先提問」「概念打包好讀、方便抉擇先後」。
- 先用選擇題確認存放形式和範圍，才寫總覽。→ `docs/design/concepts-overview.md`、`CLAUDE.md`

### 5. 第一版原型（11/03）
- 使用者選：比箭、乞丐的大廳；由 Claude 判斷形式；細節先用建議值並做成可切換的開關。
- 途中使用者補充「參考電影情節，讓特定人士知道真實身份」。依電影版劇情（化名西農、阿爾戈斯死後兒子推斷出身分、盲眼豬倌、雅典娜神像相認）加入「知情者」，範圍擴大成宮門＋大廳。
- **比箭的數值問題**：原本的重力下怎麼射都穿不過 12 孔，用模擬找出可行的數值後才修正。
- **檢查代理第一次審查**：找到會擋住遊戲的錯（選單蓋住畫面，因為 CSS 蓋過了 `hidden`），以及大廳直接走就能贏等 11 項。全部修正後發布成網頁。

### 6. 第二版：規則與畫面分離、補潛行元素（11/04）
- **需求**：「做到難移植時通知我抉擇」；比箭改第一或第三人稱；乞丐補上潛行必備、又適合本作的元素。
- **移植抉擇**：使用者選「規則抽成獨立模組」。兩個原型都拆成「純邏輯規則檔＋畫面檔」，之後搬 Unity 只要把規則翻成 C#。
- **比箭**：選第一人稱，因為「看著 12 個孔對成一線」本身就是玩法。
- **乞丐補的元素**（冷門的如擊暈、藏屍、換裝不做）：
  - 視線遮擋、光影
  - 警覺階段（？→！→ 看穿）、交頭接耳、女僕巡邏
  - 腳步聲、丟骨頭、撞倒酒罈
  - 掌燈差事、跛行、混進僕人
- **途中使用者要求「各部分用代理分工合作」**：改成三個代理同時開發，主對話負責整合（見 `ai-collaboration.md`）。

### 7. 第二次審查與修正（11/04）
- 檢查代理實測發現：
  - 大廳被一個「直接走到爐火邊」的程式玩家 56 次全贏
  - 手機上弦需要的拖曳距離超出螢幕
  - 摸老狗幾乎來不及
  - R 鍵容易誤按重來
  - 比箭的回合流程還寫在畫面檔裡
- 兩個修正代理分別處理。大廳改成「直接走過去」0% 勝率，「用差事、掩護或先得到允許」100% 勝率，「不靠允許、靠骨頭引開」約 35%。
- **最後狀態**：乞丐規則測試 31 項、比箭 17 項全過；兩個原型發布到原本的私人網址。

### 8. 融合分析（11/05）
- **需求**：「分析儲存庫（repo）各遊戲的融合搭配適不適合」。
- **做法**：重新掃過所有遠端分支，新發現 `odyssey-horror`（《奧吉吉亞》的早期版本，另一個 Unity 2022.3 專案）和 `ideas/unity-game-dev-101`（入門教材，不列入）。
- **結論**：時間線不重疊、主題相通，適合做成「連作」，不建議一開始就合成一款大遊戲。→ `docs/design/2026-11-05-fusion-analysis.md`

- 使用者決定：內容一律以電影為主，原典補充，再依整體遊戲設計適度改編。`CLAUDE.md` 已改，乞丐設計文件加上【電影】【原典】【改編】標記；已做的原型和主線等下次動到時再照新規則調整。

### 10. 融合版網頁原型（11/05～11/06）
- **需求**：期中報告（11/12，7 分鐘：試玩影片、製作過程、AI 分工、說明、改進）。使用者決定做融合版、原型程度、上 itch.io、簡報用 Gamma。

### 15. 本地真耳朵試玩：木馬之夜第一輪（11/07）
- **做法**：本地用小型伺服器包外殼開原型（claude.ai 試玩頁在內建瀏覽器要登入），使用者用喇叭試玩。
- **結果**：驟降很難分辨、聽不出要跟的慢低音、腳步合拍沒有掩護感。雲端錄音分析全過，但人耳在喇叭上聽不出核心訊號。
- **決定**：先交給雲端加強這三個聲音訊號，改完再試玩；3D 方向、假驟降、視覺淡出、暗示階梯，以及比箭和大廳復仇延到下一輪。→ `docs/process/playtest-notes.md`

### 16. 各遊戲人稱分析（11/08）
- **需求**：「分析各遊戲應該第幾人稱」。
- **結論**：整個系列統一第一人稱，因為核心是用耳朵玩，聽的位置要等於看的位置。大廳復仇維持在門檻前小範圍走動（現況已符合），岸邊點名建議用固定鏡頭，斯庫拉與卡律布狄斯待定。連帶規則：關鍵聲音在喇叭上也要聽得出來。→ `docs/design/2026-11-08-perspective-analysis.md`

### 15. 第一輪本機試玩與喇叭可聽度（11/08）
- 本機第一輪（喇叭、修正前版本）：驟降、慢低音、腳步合拍都聽不出來（`playtest-notes.md`）。本機另寫了「各遊戲統一第一人稱」分析（`2026-11-08-perspective-analysis.md`）。
- 雲端回應：關鍵訊號搬到 200～4000 Hz（木魚預告音、低音拍加中頻敲擊、碎石腳步、警戒開頭鼓聲先壓低）；錄音工具加 3 項喇叭可聽度檢查與「200 Hz 高通喇叭模擬」。預告音 +11 → +25 dB、低音拍 +10 → +13 dB、腳步突出量差 28 dB；8 項檢查全過。
- 按鍵配置：節奏鍵加滑鼠右鍵（木馬屏息、復仇舉盾）。
- 待第二輪本機試玩（喇叭與耳機各一次）。
